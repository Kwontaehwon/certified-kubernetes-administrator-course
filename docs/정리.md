# 03. Scheduling
## Manual Scheduling
원래는 kube-scheduler 가 자동으로 배치될 node를 스케쥴링하지만 Pod 가 생성되기 전 Manual 하게 배치될 노드를 선택할 수 있다.
-> **Pod 가 생성되기 전에만 적용 가능.**
### 방법 1 : `spec.nodeName` 사용
```yaml
apiVersion: v1
kind: Pod
metadata:
 name: nginx
 labels:
  name: nginx
spec:
 containers:
 - name: nginx
   image: nginx
   ports:
   - containerPort: 8080
 nodeName: node02
```

### 방법 2 : Binding 객체 생성
```yaml
apiVersion: v1
kind: Binding
metadata:
  name: nginx
target:
  apiVersion: v1
  kind: Node
  name: node02
```
    
```yaml

kind: Pod

 name: nginx

  name: nginx
```

### Annotation
Label - Selector 는 객체를 그룹화하는데 사용하는 반면 `Annotation`은 정보제공 목적
```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: simple-webapp
  labels:
	app: App1
	function: Front-end
  annotations:
	 buildversion: 1.34 # 정보제공
spec:
 replicas: 3
 selector:
   matchLabels:
	app: App1
template:
  metadata:
	labels:
	  app: App1
	  function: Front-end
  spec:
	containers:
	- name: simple-webapp
	  image: simple-webapp   
```

## Taint and Tolerations
**특정 Taint에 대해 Toleration이 있는 파드만 해당 노드에 스케줄 될 수 있음.**
> [!important]
> **Taint와 Tolerations는 파드가 특정 노드로 가도록 지시하지 않습니다**. 
> 대신, 노드가 특정 Tolerations가 있는 파드만 수용하도록 지시합니다.
> - Pod가 Node1 에 대한 Toleration을 가지고 있다고 해도 무조건 거기에 배치되는 것이 아님.
>   - 반드시 특정 Node에 배치되길 원한다면 `Node affinity` 사용



> [!example]
> 강의 예시 : Pod(벌레), Taint(해충기피제), Toleration(벌레의 내성) 
### Taint
![tn](../../images/tn.PNG)
- Taint Option
	- **`NoSchedule`** : Tolerantion 을 가진 파드만 스케줄
	- **`PreferNoSchedule`** : 가능하면 스케줄 하지 않음 (보장 X)
	- **`NoExecute`** : 새로운 파드를 스케줄하지 않고 내부에 있던 Tolernation이 없는 파드를 제거
#### 명령어
- Taint 제거 명령어
	- `kubectl taint nodes controlplane node-role.kubernetes.io/control-plane:NoSchedule-`
